# Security Policy

## Supported Versions

Security fixes are applied to the latest `main` branch and to the latest published release, when a release is available. Older snapshots may not receive security updates.

## Reporting a Vulnerability

Please do not report security vulnerabilities in a public issue.

Report vulnerabilities privately through one of these channels:

1. Use [GitHub Private Vulnerability Reporting](https://github.com/Patel230/steam-resources-library/security/advisories/new) when it is available for the repository.
2. If private reporting is unavailable, email **Lakshmanp230@gmail.com** with the subject line `STEAM Resources Library security report`.

Please include the affected file or URL, a clear description of the issue, reproduction steps, the potential impact, and any suggested mitigation. Redact credentials, personal data, and other sensitive information from the report.

## Response Process

The maintainers will acknowledge a report as soon as practical, investigate and reproduce the issue, determine its severity, and coordinate a fix or mitigation. Reporters will be credited in the release notes when they request credit and when doing so does not create a safety or privacy concern.

Please allow reasonable time for investigation and remediation before public disclosure. Do not exploit a vulnerability beyond what is necessary to demonstrate it, access or modify other users’ data, disrupt availability, or conduct denial-of-service testing.

## Scope Notes

The project is an open-source catalog and static web application. Resource links and third-party documents are external content and may have their own security, copyright, and availability policies. Do not upload secrets, private credentials, or confidential documents to issues, pull requests, catalog CSV files, or the repository.
